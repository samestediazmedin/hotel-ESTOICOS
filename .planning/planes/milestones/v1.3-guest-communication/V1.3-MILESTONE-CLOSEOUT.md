## Milestone Overview

**v1.3 "Guest Communication Hub"** ships in 2 phases (15 and 16) with 11 plans total, closing 12 REQ-IDs across extended contact capture and full guest communication workflow. The milestone transforms the guest record from a static PMS entity into a living communication hub.

Before v1.3: `Guest` records had basic contact fields (email, phone). Staff had no way to record contact attempts, no deep-link shortcuts to call/WhatsApp/email, and no visibility into who contacted a guest or when.

After v1.3: Staff sees a full guest detail page at `/guests/:id` with a 4-section layout (header + contact info + reservations + últimos contactos). Every contact attempt is recorded in `guest_contact_events` before the deep link opens. Real-time Socket.io push notifies other staff tabs to prevent duplicate outreach. Public booking form captures WhatsApp numbers, dietary restrictions, and marketing consent.

## Key Architectural Decisions (v1.3)

| Decision | Phase | Rationale |
|----------|-------|-----------|
| Explicit field mapping in GuestsService.create (no spread) | 15-01 | Prisma 7 silently drops unknown properties in `data` objects; research trap #1 mitigation |
| `Zod .optional().default()` makes field required in TS Output type | 15-01 | Test fixtures must include fields with defaults; `undefined` input still accepted |
| Native `<details>/<summary>` for collapsibles in BookingFormPage | 15-03 | Zero new deps; HTML5 semantics + keyboard-accessible without Radix import |
| `escapeHtml` applied only to free-text fields | 15-02 | E.164 whatsappNumber is machine-validated; contactPreference is enum; only dietary + specialRequests are free-text injection surface |
| `ContactMethod` at Prisma level (not just Zod) | 16-01 | DB-enforced constraint; enum lives in `generated/prisma/client` — import path requires `/client` suffix |
| `GuestContactGateway` on default `/` namespace (same as HousekeepingGateway) | 16-01 | NestJS supports multiple gateways on same namespace; no frontend config change needed |
| `onDelete: Cascade` on Guest→events; `Restrict` on User→events | 16-01 | GDPR: guest deletion cascades contact events; staff deletion is blocked (audit trail integrity) |
| `staffUserName` from Socket.io payload for toast text | 16-03 | DB-authoritative name vs auth store name may diverge (display name vs DB name); research trap #6 |
| `ExtendedGuestDto` as standalone interface | 16-04 | TypeScript TS2312: cannot extend union types; standalone interface with explicit fields is canonical |
| `Object.defineProperty` to mock `window.location.href` in jsdom | 16-04 | jsdom 26.x: `href` is non-configurable; `vi.spyOn` setter mode throws — known gotcha |
| `handleRowClick` rewired to `navigate()` in GuestsPage | 16-05 | Guest detail requires URL-shareable route; drawer pattern breaks deep linking |
| `useHousekeepingSocket` NOT migrated to `lib/socket.ts` singleton | 16-03 | Deferred cleanup to v1.4; dual connections are functionally correct at hotel scale (~5 concurrent staff) |

## Suggested v1.4 Milestone Theme

Based on v1.3 carry-forward:

### Candidate A — "Pre-Arrival Guest Experience" (recommended)
**Goal:** Automate pre-arrival communication and allow guests to self-complete their stay preparation.
- Pre-arrival reminder email cron (1 day before check-in)
- Notes field on contact events (staff adds post-call summary)
- Email templates library (welcome / pre-arrival / check-in instructions)
- Guest preferred language routing (ES/EN templates)
- `useHousekeepingSocket` → `lib/socket.ts` singleton migration (technical debt)

### Candidate B — "Payments + Online Completion"
**Goal:** Guest can complete a reservation and pay online from the portal. Revenue-enabling milestone.
- Payment gateway: PSE Colombia (Wompi / PayU) or Mercadopago
- Online reservation completion flow (replaces manual staff entry)
- E-receipt via Resend
- Folio integration: payment posts as folio line item

### Candidate C — "Contact Hub Advanced"
**Goal:** Power-user features for guest communication management.
- Contact log filters / search
- Bulk contact actions
- WhatsApp Business API outbound (Meta Cloud API)
- Contact event analytics dashboard

**Recommendation:** v1.4 = Candidate B (payments unlock revenue before guest experience polish). Then v1.5 = Candidate A+C combined.
