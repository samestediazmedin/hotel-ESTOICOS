# v1.2 Milestone Closeout — Public Data Wiring

**Closed:** 2026-05-18
**Status:** Complete — pending Phase 14 manual QA sign-off
**Milestone goal:** Eliminar toda data hardcodeada del portal público. Cada campo que un visitante ve en `hotelsumapaz.co` proviene del backend y es editable por el admin desde la zona staff.

---

## Milestone Overview

**v1.2 "Public Data Wiring"** ships in 3 phases (12, 13, 14) with 16 plans total, closing 22 REQ-IDs across Public Data API, Hotel Settings Admin, and the Public Reviews System. The milestone transforms the v1.1 visual-identity layer from a static-data shell into a live, admin-editable product.

Before v1.2: `apps/web/src/features/public-portal/data/*.ts` contained hardcoded hotel info, room types, photos, and review data. The admin had no way to change what the portal showed without editing source files.

After v1.2: Every visible field on `hotelsumapaz.co/booking` comes from the database in real time. Admin edits from `/settings/hotel` propagate to the portal within the 60-second Cache-Control window.

## Key Architectural Decisions (v1.2)

| Decision | Context | Rationale |
|----------|---------|-----------|
| `Cache-Control: public, max-age=60` on all 4 public endpoints | Phases 12 + 14 | CDN-compatible; admin edits propagate within 60s; reduces DB read load |
| Dual-shape photo URL (`p.key ? R2_URL/key : p.url`) | Phase 13-01 | Legacy `url` fixture rows (no R2 key) fall through correctly without explicit null check |
| `Reservation.reviewTokenJtiUsed` DB unique index → P2002 catch | Phase 14-01 | Atomic single-use enforcement at DB level; no application-level locking needed |
| No `@react-email/components` — inline HTML only | Phase 14-02 | Library incompatible with NestJS server-side rendering context at the time of implementation |
| Dedicated `reviews-submit` throttler (5/IP/3600s) in ReviewsModule | Phase 14-01 | Prevents TTL collision with global `short` (60s) / `long` (3600s/100) ThrottlerModule setup |
| `sendReviewInvite` re-throws vs `sendBookingConfirmation` swallows | Phase 14-02 | `reviewInviteSentAt` must only be stamped on confirmed delivery to enable retry on next cron run |
| Single-tenant simplification: JTI stored on Reservation row | Phase 14-01 | Multi-tenant would need a separate token ledger; single-tenant can use Reservation.reviewTokenJtiUsed directly |
| HTML5 native drag over @dnd-kit for gallery reorder | Phase 13-04 | Zero new dependencies; sufficient for 5–10 photos in a single-tenant PMS |
| R2 direct PUT via native `fetch` (not axios) for photo uploads | Phase 13-04 | axios interceptors inject `Authorization` header that R2 presigned URLs reject with 403 |
| `updateMany({ where: {} })` for single-row `system_config` | Phase 13-01 | Prisma `update()` requires unique `where` clause; `updateMany` with empty `where` is canonical for singleton tables |

## Suggested v1.3 Milestone Theme

Based on v1.2 carry-forward and v2 roadmap, three candidate themes for v1.3:

### Option A — "Payments + Online Completion" (recommended)
**Goal:** Guest can complete a reservation and pay online from the portal.
- Payment gateway integration: PSE Colombia (Wompi / PayU) or Mercadopago
- Online reservation completion: replaces current manual booking flow
- E-receipt sent via Resend automatically
- Folio integration: payment posts as a folio entry

### Option B — "AI Enhancements"
**Goal:** Staff AI assistant gets write-capable tools; Concierge gets live Bogotá data.
- Staff AI: `modify_reservation`, `post_charge`, `assign_cleaning_task` tools (write-capable with ADMIN approval flow)
- Concierge: Foursquare/Google Places live lookup replacing curated catalog
- AI-generated nightly audit summary sent to hotel manager via email

### Option C — "Guest Experience"
**Goal:** Guests self-serve more of their stay.
- Self check-in: guest receives PIN + check-in instructions by email before arrival
- WhatsApp integration (Twilio / Meta Cloud API) for booking confirmations
- Guest loyalty / return-visit tracking

**Recommendation:** Option A first (revenue-enabling), then Option C (guest experience), then Option B (AI depth).
