### Defense-in-depth — 3 layers

1. **OpenAI tools filter** — `getToolDefinitionsForRole(role)` filters the JSON Schema passed to the LLM. LLM never even sees forbidden tools.
2. **Tool executor role gate** — Even if LLM tries to invoke a forbidden tool (cached, prompt injection), `ToolExecutorService` throws `ForbiddenException` BEFORE handler runs.
3. **Audit log** — Rejected calls produce audit entry with `outputStatus: 'rejected'` + `errorMsg: 'role_not_allowed: {ROLE}'`. Distinct from validation/execution errors for forensic clarity.

### Role-aware second system message
Locked `SYSTEM_PROMPT` const preserved (security AI-07). Added `buildRoleContextMessage(role)` — a switch on compile-time literals (NO user-input interpolation). Injected as SECOND `role: 'system'` message:
- ADMIN: "Tienes acceso completo al PMS"
- MANAGER: "Tienes acceso completo a operaciones y KPIs"
- RECEPTION: "NO tienes acceso a KPIs financieros"
- HOUSEKEEPING: "NO tienes acceso a información de huéspedes, reservas, finanzas o KPIs"
